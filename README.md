# GSU Virtual Academic Advisor (Agentic LLM System)

An advanced, privacy-first Retrieval-Augmented Generation (RAG) system designed to autonomously compare unstructured student transcripts from Galatasaray University (Computer Engineering Department) against official graduation requirements (ECTS).

## 🎯 Project Overview

This project serves as an intelligent academic assistant. It solves the complex problem of manually tracking graduation requirements by utilizing an **Agentic LLM pipeline**. The system processes student transcript PDFs, extracts key academic metrics, and evaluates them against departmental rules stored in a vector database. By leveraging native LLM SDKs (Kloudeks API & Google GenAI), the architecture ensures dynamic context retrieval, structured JSON generation, and strict data privacy.

## 🧠 Architecture & Key Features

### 1. LLM-Driven Semantic Ingestion
Instead of naive line-by-line splitting, the system uses a Gemini-powered chunker (via the new `google-genai` SDK) to read raw, noisy regulation documents and extract logical, standalone rules into strict Pydantic-validated JSON formats. These chunks are then embedded using Kloudeks' `qwen3-embedding-8b` and pushed to a **Qdrant** cloud cluster.

### 2. Document Parsing & MD5 Caching (Privacy-First)
Students upload their digital transcripts as PDFs.
- **Extraction:** Parsed swiftly using `pypdf`.
- **Memory-Safe Caching:** Implements an MD5 hash-based caching mechanism (`MAX_CACHE_SIZE = 50`) to prevent duplicate API calls and memory leaks, ensuring near-zero latency for repeated uploads.
- **Core Engine:** Transcript text is structured into JSON prioritizing the domestic **Kloudeks API (`qwen3.5-35b`)** to ensure student data privacy.

### 3. True Agentic Loop & Tool Calling
The core agent is powered by Kloudeks' massive **`gpt-oss-120b`** model.
- **Smart Routing & Decisions:** The agent evaluates user queries and autonomously decides whether to answer directly or utilize its toolset.
- **Tool Execution:** The agent can dynamically invoke tools like `search_graduation_rules` (Qdrant vector search) and `get_student_transcript` (parsed JSON retrieval) to formulate definitive graduation status reports.

### 4. Live MCP Server (Model Context Protocol)
The project exposes a **live SSE-based MCP Server** mounted directly onto the Gradio application at `/mcp/sse`. This allows any MCP-compatible client (Claude Desktop, Claude Code, Cursor, etc.) to connect and use the system's tools over the internet — no local setup required. External LLMs can autonomously discover and call `search_graduation_rules` to query the GSU knowledge base in real time.

### 5. YAML-Based Prompt Management & Observability
- All system prompts are decoupled from core logic and managed via `src/config/prompts.yaml` and **Langfuse** for zero-downtime prompt engineering.
- Fully integrated with **Langfuse v4** via `propagate_attributes`, allowing deep observability into the agent's reasoning loop, tool execution steps, and token usage.

## 📂 Directory Structure

```text
├── data/
│   ├── processed_chunks/   # JSON rules generated by semantic chunking
│   └── raw_docs/           # Raw graduation directives and markdown files
├── src/
│   ├── config/             # Pydantic settings, YAML prompts, and env validation
│   ├── ingestion/          # Scripts for extraction, LLM chunking, and Qdrant push
│   ├── rag/                # Core Agent logic with Tool Calling and Semantic Retriever
│   ├── tools/              # Transcript parsing utilities
│   └── utils/              # Langfuse v4 observability wrappers
├── app.py                  # Gradio UI + MCP SSE server (single-port deployment)
├── mcp_server.py           # FastMCP tool definitions (mounted by app.py, also runnable standalone via stdio)
├── Dockerfile              # Hugging Face Space Docker configuration
├── requirements.txt        # Pinned runtime dependencies
├── requirements-ingestion.txt  # Additional dependencies for local ingestion pipeline
└── .env.example            # Template for required API keys
```

## 🚀 Local Setup & Installation

**1. Clone the repository and enter the directory:**
```bash
git clone https://github.com/hamzayakar/gsu-advisor.git && cd gsu-advisor
```

**2. Set up a Virtual Environment (Recommended):**
```bash
python -m venv venv
# Windows: venv\Scripts\activate
# Mac/Linux: source venv/bin/activate
```

**3. Install dependencies:**
```bash
pip install -r requirements.txt
```

**4. Environment Variables:**
Copy the template and fill in your API keys (Kloudeks, Qdrant, Langfuse).
```bash
cp .env.example .env
```

**5. Run the application:**
Launch the Gradio interface and MCP server together on `http://localhost:7860`.
```bash
python app.py
```

## 🔌 MCP Integration

The MCP server is live at `/mcp/sse` alongside the Gradio UI. Any MCP-compatible client can connect directly.

**Claude Desktop configuration** (`claude_desktop_config.json`):
```json
{
  "mcpServers": {
    "gsu-advisor": {
      "url": "https://hamzayakar-gsu-advisor.hf.space/mcp/sse"
    }
  }
}
```

**Standalone stdio mode** (for local development):
```bash
python mcp_server.py
```

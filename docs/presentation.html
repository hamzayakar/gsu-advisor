An Agentic LLM System for Graduation Requirement Analysis

A tool-calling agent that reads your transcript, retrieves the official Computer Engineering ECTS rules, and tells you where you stand — with sources.

Hamza Yakar & Team Galatasaray University · CE github.com/hamzayakar/gsu-advisor
Q1

Why we picked this project

The actual pain

Every CE student has, at some point, opened the Bologna page, tried to figure out if they have enough technical electives, and given up.

  • Rules buried in footnotes & table cells
  • INF291 / INF399 internship rules — tribal knowledge
  • F / IA / NP grades shown with credits on e-devlet PDFs

Why it’s a good GenAI problem

  • Retrieval-heavy — the LLM has to look things up
  • Cross-source — rule book and personal transcript
  • Agentic — needs to decide which source to hit, when
  • Privacy-sensitive — perfect excuse for a Turkey-hosted LLM

More honest than “summarise this PDF” demos.

Q3

What is special about our design

No LangChain

Native OpenAI + google-genai SDKs only. <1k LOC, 40-line agent loop, clean traces.

LLM-driven chunking

Gemini reads full HTML, emits Pydantic-validated rule sentences. Replaced table-fragment retrievals with coherent rules.

Privacy-aware routing

Transcripts $\rightarrow$ Kloudeks (TR-hosted) only. Google sees the public rule base — never student data.

Live MCP server

Same tools exposed via SSE at /mcp/sse. Claude Desktop / Cursor / Claude Code connect with one line of config.

Prompts as data

YAML + Langfuse override. Zero-downtime prompt tuning. Full agent reasoning observable.

Hard memory ceilings

MD5-keyed transcript cache, capped at 50. No leaks on the shared HF Space.

Algorithms — and why

Why this, not something else

qwen3-embedding-8b
The only embedding model the Kloudeks tenancy exposes. Privacy constraint forces us through Kloudeks, so this was a constraint, not a comparison won.

Managed; payload filtering; new query_points API with score thresholds.

Long context + constrained decoding kills the “model wrapped JSON in markdown” bug.
Parser/Router

Narrow JSON-emission tasks. We also tried a Qwen reasoning model here — ate +600 s per turn. See Q7.
Agent
gpt-oss-120b
Reliable tool calling; chains transcript $\times$ rule lookups. The largest chat model Kloudeks gave us.

Why an agent loop, not single-shot RAG?

“Do I have enough technical electives?” needs both the rule and the transcript. Single-shot can’t decide which store to hit, much less both. The loop fetches what it needs, in the order it needs it.

Q5

The data

Source 1 — ECTS regulations

  • Scraped from ects.gsu.edu.tr/.../12
  • ~200 kB cleaned HTML → ~150 standalone Turkish rule sentences after Gemini chunking
  • Each chunk: topic, related_course_code, rule_type
  • Embedded once, served from Qdrant

Source 2 — student transcripts (runtime)

  • Two flavours: GSU PDF + e-devlet PDF
  • e-devlet quirk: shows credits even for F / IA / NP — compensated in prompt + post-processing

Parsed transcript schema

{
  "total_credits_completed": 192.0,
  "gpa": 3.12,
  "failed_courses": [
    {"code": "INF112", "grade": "F"}
  ],
  "all_passed_courses": [
    {"code": "MAT101", "credits": 6.0},
    ...
  ]
}

Small enough to drop verbatim into the agent’s context when requested via get_student_transcript.

Q6

Related work & literature

1. Vector-DB RAG advisors

The CourseGPT / AskUni / EduBot family. Split FAQs into 500-token chunks, embed, retrieve, stuff into prompt.

Works for FAQs — fails when answer needs your data.

2. Curriculum planners

DegreeWorks et al. Every rule hand-coded in a rule engine; transcript parsed by fixed regex.

Robust but rigid — new rule means new code.

3. Agentic tool-calling

ReAct (Yao et al., 2023) + OpenAI function calling. Closest analogue to us.

Our additions: LLM-chunked rules, privacy-aware routing, live MCP.

Turkish embedding contenders — in theory

multilingual-e5-large BGE-M3 qwen3-embedding-8b ← what Kloudeks gave us

Privacy constraint forced our hand — the Kloudeks tenancy only exposes one embedding model, so we didn’t compare these in practice.

Q7

What we measured — and what we didn’t

No formal benchmark. Here’s why.

The Kloudeks tenancy we’re on exposes:

  • 1 embedding model — qwen3-embedding-8b
  • 1 large chat model — gpt-oss-120b
  • 1 smaller chat model — qwen3.5-35b
  • 0 vision models — would have parsed transcripts straight off the PDF pages with a VLM if available; using pypdf text extraction instead.

Privacy constraint rules out non-Kloudeks alternatives just to fill a comparison table. With one option per layer, there is no like-for-like benchmark to run, so this section is descriptive rather than tabular.

The one real data point we have

Tried: Qwen reasoning model on parser + router

End-to-end latency jumped by ~+600 s per turn. The reasoning model’s deliberation phase fired twice in sequence (parser, then router) before the agent even started generating.

Reverted both layers back to qwen3.5-35b. A single point, not a controlled experiment, but real — and the reason we use a non-reasoning model at the narrow-task layers.

What we can vouch for

  • Pipeline works end-to-end locally against both GSU and e-devlet PDFs
  • Agent reliably chains both tools — visible in Langfuse
  • 4–7 s warm-turn latency, dominated by 120B generation
  • Score threshold 0.45 set by eye, not by formal sweep
Q8

What went wrong along the way

Naive chunking destroyed retrieval

Recursive char splitter on HTML → fragments of tables. Even the 120B agent couldn’t read them.

Fix: Gemini semantic chunker

Pydantic-constrained, standalone sentences. Replaced table-fragment retrievals with coherent rule sentences.

Tool-call hallucinations

Agent called get_transcript 4× in a row, or searched with an empty string.

Fix: red-line prompt + hard cap

Explicit “call each tool at most once per turn” rule, plus a 4-iteration safety cap.

Memory leak on HF Space

Unbounded transcript cache + Gradio tempdir paths → RAM grew with every upload.

Fix: MD5-key + 50-entry ceiling

Commit 19b8bb2. Bounded, deduplicated, near-zero latency for re-uploads.

e-devlet PDFs lie about credits

F / IA / NP courses still show credits → parser over-reported completion.

Fix: prompt rule + post-processing

Failure grades forced to zero credits regardless of what the PDF claims.

Live deploy blocked by Kloudeks IP allowlist

HF Space’s egress reads as a private / cloud IP from Kloudeks’ side → outbound requests rejected. Locally: everything works end-to-end.

Status: code-side done, network-side pending

Code, prompts, tools, MCP surface — all demonstrable locally. Production endpoint dark until allowlisting on Kloudeks side — fix lives outside our codebase.

Also: Qdrant search deprecation, Langfuse v3→v4 migration, markdown JSON fences from the parser, whitespace queries spinning up the full loop. All in the report.

Q9

What could be done next

Quality

  • Cross-encoder re-ranker (bge-reranker-v2-m3) → cut the off-topic retrievals we still see by eye
  • An actual eval set — ground-truth answers reviewed with seniors, re-runnable on every change
  • Token streaming — kills the 4–7s silence per turn for free

Features

  • Graduation checklist view — deterministic, every requirement ticked off
  • Course recommender — CSP solver exposed as a new agent tool

Scale

  • Multi-department support — ingestion pipeline is generic; new dept = new URL + label
  • User accounts — persistent cache across redeploys

Hardening

  • MCP auth + rate limits before any real production deploy
  • Tighter golden-set regression tests in CI
Closing

Takeaways

  • Structural choices > model choices. Semantic chunking, agent loop, externalised prompts — each mattered more than picking the biggest model.
  • Agent loop beats single-shot RAG structurally for anything that needs both the rule book and the transcript — observable, turn by turn, in Langfuse.
  • Privacy & observability are not afterthoughts. Baking them in from day 1 cost very little and paid off on every bug.
  • An MCP server fell out of the design almost for free — the best kind of bonus feature.
  • Caveat: currently live only locally — Kloudeks rejects the HF Space’s egress IP. Code-side done; network-side pending.
